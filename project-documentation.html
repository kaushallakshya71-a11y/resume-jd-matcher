Project Title & One-line Summary
🎯 Project Title: ResumeMatch AI — Smart Resume & Job Description Analyzer

📌 One-line Summary: Ek AI-powered web tool jo tumhara resume paste karo aur koi bhi job description paste karo — aur instantly bata deta hai ki tum us job ke liye kitne percent match ho, kya skills missing hain, aur kaise apply karna chahiye.

Seedha baat karo toh — jab bhi hum job apply karte hain, hume confuse hota hai ki "kya mera resume is job ke liye theek hai?" ResumeMatch AI isi confusion ko solve karta hai. Tum apna resume aur job ka description dono paste karo — tool 2 second mein sab analyse kar deta hai.

Q2
Question 2
Why Did You Build It? Real-world Motivation

Real pain point yeh tha: India mein har saal lakho students aur freshers job applications bhejte hain — lekin 75% rejections is liye hote hain kyunki unka resume ATS (Applicant Tracking System) se pass nahi hota. Company ka HR kabhi directly resume nahi dekhta pehle — ek computer software (ATS) pehle filter karta hai.

💡 Real Story: Ek student ne 200+ jobs apply kiye lekin single interview nahi mila. Reason? Uska resume theek tha lekin job description ke keywords match nahi kar rahe the. ATS ne sab reject kar diya bina kisi human ne dekhe.
3 Real Problems Jo Dekhe
  • 1
    ATS Invisibility Problem 👻
    90% companies ATS use karti hain (TCS, Infosys, Google, Amazon sab). Agar resume mein exact keywords nahi hain jo JD mein hain — toh automatically reject. Koi human nahi dekhta.
  • 2
    Skills Gap Awareness Nahi 😶
    Fresher ko pata hi nahi hota ki exactly kaunsi skill missing hai. Bas "rejected" aa jaata hai — koi explanation nahi. Isse career growth slow ho jaati hai.
  • 3
    Existing Tools Expensive Hain 💸
    Resume.io, Jobscan jaise tools ₹800–₹2000/month charge karte hain. Ek student ya fresher ke liye afford karna mushkil hai. Free version mein features bahut limited hote hain.

Isliye build kiya — ek ऐसा tool jo completely free ho, koi login na chahiye, koi data upload na ho, aur result instant mile. Privacy first — sara analysis user ke browser mein hi hota hai, koi data server pe nahi jaata.

Q4
Question 4
Your Solution — End-to-End Kya Build Kiya?

Maine ek complete AI-powered web application build kiya jo 9 alag-alag modules mein kaam karta hai. Har module ek specific problem solve karta hai.

9 Core Modules
  • 1
    🎯 Smart Match Score Engine
    Resume aur JD dono se skills extract karta hai — Skill Taxonomy (600+ skills) use karta hai. Weighted scoring: Skills 40% + Experience 20% + Domain 15% + Soft Skills 15% + ATS 10%.
  • 2
    🔍 Skills Gap Analyzer
    JD mein jo skills hain aur resume mein jo nahi hain — unki exact list. High Priority vs Nice-to-Have categorize karta hai. Learning resources bhi suggest karta hai (free sources).
  • 3
    🤖 ATS Analysis Engine
    Keyword density check karta hai. Pass probability percentage deta hai. Specific ATS-friendly improvements suggest karta hai (formatting, keywords, sections).
  • 4
    💼 Company Optimization
    Startup vs MNC vs Product company ke liye alag resume tips. Tone, length, focus areas — sab company type ke hisaab se customize hota hai.
  • 5
    📋 Resume Tips Generator
    Role level (Fresher/Mid/Senior) ke hisaab se specific actionable tips. 20+ personalized suggestions generate hoti hain.
  • 6
    🗺️ Career Roadmap
    3-phase plan: Phase 1 (0–3 months), Phase 2 (3–6 months), Phase 3 (6–12 months). Next role suggestions based on current skills.
  • 7
    🎤 Interview Prep
    Resume + JD ke basis pe customized interview questions generate karta hai. STAR format mein answers kaise dein — tips bhi deta hai.
  • 8
    ⚠️ Career Risk IQ
    5 modules: Learning Adaptability, Consistency Stability, Skill Decay Index, Automation Risk, Direction Clarity. Batata hai ki 2 years baad career kaisi hogi.
  • 9
    📚 Local History Database
    IndexedDB (browser ka built-in DB) use karke saari analyses save hoti hain. No account, no server — completely local aur free.

Question 5
Tech Stack Justification — Kyun Yeh Choose Kiya?
Technologies Used
HTML5 CSS3 Vanilla JavaScript IndexedDB Render (Hosting) serve (npm) PDF.js (CDN) Google Fonts GitHub (Version Control)
Technology Kyun Choose Kiya Alternative Kya Tha
Vanilla JS (No Framework) React/Vue use karne se build step chahiye hota — Render pe complexity badti. Vanilla JS seedha browser mein chalta hai, zero setup, zero cost. React — lekin overkill tha is simple app ke liye
IndexedDB (Browser DB) Firebase/Supabase = paid ya account needed. IndexedDB = browser ka built-in database, 100% free, no server, no privacy risk, offline bhi kaam karta hai. Firebase Firestore — lekin charges lagte
CSS Custom Properties Design system banane ke liye — ek jagah color change karo, poori app change ho jaati hai. Dark/Light mode toggle bhi isi se possible hua. Tailwind CSS — lekin CDN version limited hai
Render (Hosting) Free tier available, auto-deploy from GitHub, SSL certificate free, custom domain support. Heroku ne free tier band kar diya tha. Vercel, Netlify — dono theek hain lekin Render already setup tha
serve (npm package) Static files serve karne ke liye — sirf ek dependency. Nginx setup karna complex hota. Nginx, Apache — lekin configuration complex hai
PDF.js (CDN) Users PDF resume upload karte hain — PDF.js se browser mein hi text extract hota hai, server pe nahi jaata. Privacy maintain rehti hai. Server-side PDF parsing — privacy risk hota
🧠 Key Decision: "No backend, no database server, no API calls" — yeh deliberate design choice tha. Jab koi backend nahi hai, toh koi server crash nahi, koi downtime nahi, koi cost nahi, aur koi data breach nahi. Pure client-side app = maximum reliability at zero cost.

    User Input (index.html → app.js)
    User resume aur JD paste karta hai ya PDF upload karta hai. app.js ka runAnalysis() function trigger hota hai "Analyze Match" button click pe.
  • 2
    PDF Extraction (PDF.js CDN)

  • 3
    Text Normalization (analyzer.js)
    normalizeText() function — lowercase karo, special characters hata do, whitespace clean karo. Fir extractSkillsFromText() se 600+ skills mein se match dhundo.
  • 4
    Weighted Scoring (analyzer.js)
    Skills match (40%) + Experience years comparison (20%) + Domain detection (15%) + Soft skills (15%) + ATS keywords (10%) = Final Score 0–100%.
  • 5

    Ek hi pass mein sab generate hota hai: missingSkills, strongMatches, atsAnalysis, companyOptimization, resumeTips, roadmap, interviewPrep, strengthsWeaknesses, verdict.

Database Schema & APIs
ℹ️ Important: Yeh app "serverless" hai — koi backend API nahi hai, koi REST endpoint nahi hai. Sab kuch browser mein hota hai. Database bhi browser ka built-in IndexedDB use karta hai.
IndexedDB Schema (Local Database)

IndexedDB ek browser-level database hai — SQL jaisa lekin NoSQL structure. Hamare paas 3 Object Stores hain (SQL mein "tables" bolte):

Object Store (Table) Key Fields (Columns)
matchHistory id (auto-increment) score, verdict, missingSkills[], strongMatches[], targetRole, atsPassProbability, resumeSnippet (2000 chars), jdSnippet (2000 chars), breakdown, createdAt (timestamp)
riskHistory id (auto-increment) overallScore, riskCategory, currentRole, yearsOfExperience, salaryGrowth, automationRisk, topRiskFactors[], projection, individualSignals, createdAt
resumeVersions (v2 New) id (auto-increment) name, resumeText, targetRole, notes, createdAt, updatedAt
jobApplications (v2 New) id (auto-increment) company, role, location, salary, jobUrl, status, dateApplied, matchScore, versionUsed, notes, createdAt, updatedAt
stats "main" (single doc) totalMatchAnalyses, totalRiskAnalyses, avgMatchScore, topMissingSkills[], lastActive

Major Technical Challenges & Resolution
🔴
Challenge 1: Render Build Repeatedly Fail Ho Raha Tha
🐛 Problem

Render pe deploy karte time "Exited with status 1" error aa raha tha. Multiple commits kiye lekin har baar fail. Root causes: (a) android/ folder ke 79 files git mein the — Render Android Gradle build try karta tha. (b) yarn.lock + package-lock.json dono the — package manager conflict. (c) render.yaml dashboard settings se conflict kar raha tha. (d) "node": ">=22.0.0" — Render Node 20 use karta tha.


✅ Resolution

Step 1: git rm -r --cached android/ — Android files permanently remove kiye.
Step 2: render.yaml delete kiya — dashboard settings conflict nahi hota ab.
Step 3: Dono lockfiles .gitignore mein daale — Render fresh install karta hai.
Step 4: package.json ultra-minimal rakha — sirf serve dependency.
Result: Clean build in 2.15 seconds ✅

🟡
Challenge 2: Skill Matching Mein False Positives
🐛 Problem

Simple text search se "Java" search karne pe "JavaScript" bhi match ho jaata tha. "Go" search karne pe "good", "google" bhi match ho jaate the. Scoring inaccurate ho raha tha.


✅ Resolution

Word boundary regex implement kiya: /\bjava\b/i — yeh sirf exact word match karta hai.
ALIASES system banaya: "js" → "javascript", "node.js" → "node" taaki variants handle ho sakein.
Longest-match-first algorithm: pehle "react native" match karo, fir "react" — taaki substring conflict na ho.

🟠
Challenge 3: Firebase Chargeable Tha — Free Alternative Chahiye Tha
🐛 Problem

Pehle Google Firebase + Firestore implement kiya tha history save karne ke liye. Lekin Firebase account, config keys chahiye the aur potential charges ka risk tha. User ne free alternative maanga.


✅ Resolution

Firebase ko completely remove kiya — teen CDN script tags hata diye.
Same public API maintain rakhi (FirebaseDB.saveMatchAnalysis()) taaki app.js change na karna pade.
Browser ke built-in IndexedDB use kiya — zero cost, zero account, offline bhi kaam karta hai, up to 50MB+ storage.

🔵
Challenge 4: PDF Upload Privacy Issue
🐛 Problem

PDF resume upload karne pe server pe bhejne se privacy risk hota. Log nahi chahte ki unka resume kisi server pe store ho.


✅ Resolution

PDF.js CDN library browser mein hi PDF parse karta hai. FileReader API use kiya — file ko ArrayBuffer mein convert karo, PDF.js se pages read karo, text extract karo. Server pe kuch nahi jaata. 100% client-side.
